# 通用视觉导航 agent

由具体业务模块通过 Python 代码调用，使用官方 `claude-agent-sdk==0.2.152`。
安装项目时由 pip 自动安装，不需要额外运行时。

`claude_runner.py` 用 Claude Agent SDK 的 `ClaudeSDKClient` 驱动完整会话和工具循环：
截图 → 模型在同一次工具调用中给出画面事实与动作 → 本地判断事实 → 单次 WASD 移动 → 等待 0.5 秒 → 重新截图。
`move` 和 `finish` 是 SDK 的进程内 MCP 自定义工具，`move` 返回移动后的图片。
两个工具都直接接收结构化事实字段，`move` 另外接收 `direction`，完成状态由本地规则推导。
原生工具参数使用平铺字段，不嵌套 `evidence` 对象或 JSON 字符串。
SDK 管理会话、工具调用、权限和请求轮次；移动工具在执行 ADB 前检查页面、完成条件和移动上限。

模型、接口地址和密钥通过 `MultimodalClient` 接入[网关路由](../README.md)，超时沿用任务配置。鱼玩和 DeepSeek 官方均由 `compat_runner.py` 中的 OpenAI 兼容 Python SDK 调用；网关显式声明协议，因此没有 `/v1` 后缀的 DeepSeek 官方地址也使用正确适配。保留的旧 Claude Messages 客户端仍由 `claude_runner.py` 驱动，入口在 `runner.py` 统一选择。

路由在每次 HTTP 尝试前原子执行 Redis `INCR`，返回值对有效渠道数取模，同时替换 URL、key 和模型名；导航 SDK 的会话历史、工具调用结果和当前截图保留，不启动本地 HTTP 转发端口。OpenAI 兼容导航使用 `multimodal/transport.py` 中的异步 HTTP 客户端，在当前请求内部处理重试，SDK 自带重试关闭：只有 HTTP 200 算成功，其他状态（包括 400、401、403）和网络异常在共享任务执行范围内持续重试至任务截止时间；脱离共享任务单独调用时最多重试3次。重试间隔10秒，受剩余时间约束，重试不会重新执行游戏移动。请求及等待受总预算约束，取消导航会中断当前路由、网络请求或重试等待。普通 JSON 图片识别沿用相同的重试规则。旧 Claude Messages 导航由 Claude SDK 处理最多3次请求重试及退避间隔；完成检测仍会停止当前会话和其自有子进程。

## 秘境内部调用

秘境的毒风导航实现仍保留，但当前默认绕过；无需额外启动命令或传命令行参数。默认流程为：

1. 出战后的加载与提示处理完成，`secret_realm/pre_battle.py` 通用读取顶部中央、计时器上方实际显示的完整副本名称，包括“阴阳秘境”“毒风秘境”“落岩秘境”等，不根据背景、人物或 BOSS 名称猜测。
2. 集中的 `SKIPPED_REALMS = frozenset({'阴阳秘境', '毒风秘境', '落岩秘境'})` 默认跳过这三个秘境，均调用 `exit_secret_battle()`，执行暂停 → 退出战斗 → 确认。每步点击前重新截图复查，确认按钮必须与退出提示出现在同一帧。
3. 主动退出后沿用秘境收尾流程回房间，重新读取挑战券；有券且出战前复查通过就继续，零券结束，未知券数不出战。主动退出不计入已结束战斗数，也不要求券数下降。
4. 其余已识别秘境进入通用战斗模块；毒风的导航 agent 当前不会被调用。

以后从 `secret_realm/pre_battle.py` 的 `SKIPPED_REALMS` 移除“毒风秘境”，即可恢复下面保留的原导航分支，无需新配置：

1. `secret_realm/navigation.py` 的 `navigate_to_poison_seal()` 传入目标、摇杆配置、毒风事实判定规则和本地 BOSS 检测回调。
2. 每轮模型在 `move` 或 `finish` 参数中给出 `page`、`boss_visible`、`battle_started`、`seal_prompt_visible`、`visible_text` 和 `observation`。
3. 本地规则确认当前是战斗页面、待解封提示明确消失，并有 BOSS 或实际交战的正向证据，才进入通用战斗模块。即使模型请求 `move`，事实已经满足完成条件时也直接成功，不再多移动一步。
4. 满50步仍在战斗页面且未确认完成，则复用同一个退出函数，回房间重新读券，主动退出不计入已结束战斗数。

以下毒风画面事实、完成检测与移动规则说明均用于以后恢复导航，默认跳过名单生效时不执行。

中央仍显示“解开『封印』，召唤 BOSS”或提示是否消失未知时，状态仍为待完成。
`seal_prompt_visible`、`boss_visible`、`battle_started` 严格使用 `yes`、`no`、`unknown` 三选一字符串，分别表示事实成立、不成立和无法确认，不接受布尔值或字符串 `True` / `False`。
人物脚下的蓝色选中圈、靠近疑似封印和提示消失本身都不足以放行。
毒风是2D场景：导航以人物脚下蓝圈中心作为地面定位点，比较它与封印地面触发区域或光柱底部的位置，再选择方向。头部、身体或悬浮“封”字的重合不代表人物已到达；每步观察需要说明两个地面位置的方向偏差。站位进入封印区域后，仍按待解封提示和 BOSS/交战证据判断是否完成。
明确的失败、胜利或结算页面返回 `finished`，停止导航并交给秘境结算流程；即使模型同时请求移动，也不会再导航、攻击或尝试暂停退出。收尾先确认是否已回房间，否则关闭结算，回房间后重新读券，有券且出战前复查通过就继续，零券结束。其他或无法确认的页面仍返回 `blocked` 并停止，不自动点击。
画面事实和动作来自同一次 SDK 模型响应，由代码检查事实之间及事实与动作之间的一致性。
毒风导航同时启用本地完成检测：初始帧、移动前后和模型响应后均检查画面；等待模型时每 0.5 秒重新截图。底部 BOSS 名称、风徽章和长红血条同时匹配，才确认 BOSS 已出现；不增加远程视觉请求。不匹配时继续原模型判断。
本地确认后锁定完成状态、取消当前 SDK 请求，不再等待接口重试；迟到的模型动作不能继续移动。秘境探险流程收到导航成功后立即调用现有公共战斗模块，战斗模块自身逻辑保持不变。

默认跳过名单之外的已识别秘境继续原有战斗流程。副本名称无法识别时重新截图重试，超过调用或等待上限则停止；退出失败也会停止，不重复出战。以后恢复毒风导航时，导航模型报错或非法动作仍抛出异常，不进入战斗。

## 在其他模块复用

```python
from naruto_daily.multimodal.agent import run_agent

# 业务模块提供已连接的 adb、已配置的 model，以及目标和当前布局的摇杆位置。
result = run_agent(adb, model, goal_prompt, joystick=joystick, max_steps=50)
if result.reached:
    continue_task()
elif result.status == 'max_steps':
    exit_task()
```

默认通用工具直接使用 `{"status": "pending", "observation": "可见依据"}` 等事实字段，
其中 `status` 必须选择 `pending`、`reached` 或 `blocked` 中的一个值。
毒风模块提供专用事实字段和本地判定规则，不接收模型自报的 `reached` 布尔值。

W/A/S/D 对应上/左/下/右，实际通过 ADB 从摇杆中心向目标方向滑动一次。
项目使用固定 1920×1080 布局，秘境模块中的摇杆中心 `(327, 825)` 经毒风未解封场景实机校准，
半径 80、单次滑动 300 毫秒。布局变化时由代码中的场景配置调整，不交由模型生成点击坐标。
校准后连续两次向右移动，人物脚下位置基本保持同一水平，修正旧中心偏下导致的右移下漂。

最多 50 次移动，正常最多 51 次模型请求，包括最后移动后的画面判断。
如果事实仍为待完成，模型却提前调用 `finish`，SDK 使用 `ModelRetry` 在同一会话、同一截图上要求修正，
整个导航最多允许 3 次此类重试，因此总请求上限为 54 次，已执行步数不重置。
持续矛盾超过额度则停止，不进入战斗。第 50 步之后未完成时，`finish` 或再次请求 `move` 均返回 `max_steps`，不会执行第 51 步。
最后一帧事实确认完成仍视为成功；非战斗状态优先停止，不会作为正常步数耗尽去点击退出。

每轮只接受一个工具调用，纯文本“完成”不算成功；错误参数、一次请求多个动作或不完整响应均停止。
`AgentResult.history` 是已执行动作及其移动前观察，`observation` 是最终事实判定依据。
网络和设备失败不会重试动作。成功、异常和取消都会关闭 HTTP 连接。

测试：`python -m pytest` 通过本地 OpenAI 兼容服务运行真实 SDK 工具循环，并覆盖秘境业务分支。
测试将 SDK 回调与原有 JSON 识别分开，确保导航不会偷偷增加独立视觉请求。
实机移动校准与离线测试分别验证坐标效果和导航控制流程。
