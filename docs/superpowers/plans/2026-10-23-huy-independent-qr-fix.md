# 独立扫码入口修正

用户要求抓号器独立运行，不启动火影忍者。已撤回本次尝试的游戏日志观察方案及其所有权限、服务和组件控制。

参考依据：用户提供 `无奇抓号器.apk.1` 的 MainActivity.openAuthQRPage 直接打开 QQ `xui.ptlogin2.qq.com/cgi-bin/xlogin`，使用网页平台参数 `pf=openmobile_web`，WebView 允许第三方 Cookie；没有启动游戏、读取游戏日志或动态获取签名的代码。

修正：自写抓号器改用同一公开网页入口和对应参数，保留自己的随机 state、本轮回调隔离、严格完整授权校验、QQ `/me` 核验、私有保存和测试云端上传。增加 QQ 100044 的明确状态提示，失败不会显示上传成功。上传在健康检查后和发送前检查取消状态。

验证：运行纯 Java 授权与云端取消规则测试、构建签名 APK、只更新 3 号实例，确认 HUY1 会话保留、扫码页在抓号器进程中、清单无游戏日志权限。最后需要用户实扫，才能确认 QQ 当前是否接受网页入口，并验证新授权上传。
