# 日常模块超时截图实施计划

**Goal:** 每次非秘境模块调用满 600 秒截图，上传独立 OSS 目录。

**Architecture:** 子进程统一报告模块边界，父进程后台监控；复用现有 OSS 客户端。异常诊断与主流程结果隔离。

**Tech Stack:** Python、asyncio、ADB、现有 oss2。

**Spec:** `docs/superpowers/specs/2026-10-29-module-timeout-design.md`

## 约束与验证重点

- 600 秒阈值、每次调用一次、秘境排除、返回主界面包含。
- 同名模块重复调用独立计时，不因日志或重试重新计时。
- 子进程卡住仍能截图，任务退出取消未触发的计时并处理已开始的上传。
- OSS 上传失败不改变原任务状态，禁止覆盖已有图片，不被二维码清理删除。
- 提交信息中文，分支 `codex/adb-stall-screenshots`，推送到远端同名分支。

## 已确认的实现与审查记录

- 模块上下文只在扫码 worker 中启用，独立 CLI 保持原行为。
- 返回主界面的内部调用也计时；父模块的总耗时仍包含内部调用。
- 截图和异常上传均使用独立线程，避免并发任务的 stdout/stderr 读取占满公共线程池。
- 独立审查发现上传等待超时后重发会与未结束的 SDK 写入重叠。已通过真实存储适配器和延迟内存桶复现，再改为最多 3 次尝试共用 45 秒预算；原请求未结束时不重发。
- 审查修复后相关 86 项测试通过。最终完整回归 `.venv-login-service/Scripts/python.exe -m pytest -q`：4404 项通过，1 条 Starlette/AnyIO 依赖弃用提醒，用时 467.10 秒。
