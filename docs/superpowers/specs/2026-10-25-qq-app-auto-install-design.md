# QQ 辅助应用自动补装

用户希望雷电启动后检查抓号器和上号器，缺失时自动下载安装到当前实例；下载或安装失败时继续尝试原 QQ 扫码流程。既有应用不覆盖、不卸载。延续原任务范围：QQ 安卓/iOS 日常和周胜使用两款辅助应用，微信和仅生成二维码流程保持原样。

## 实现选择

复用现有私有 OSS 与 Cloudflare 配置。相比公开 APK URL，私有 OSS 不需要调整公开访问权限；相比把 APK 编进仓库，固定版本对象和摘要允许独立发布。父进程使用已有 OSS 身份生成带 Date 的固定 GET 请求头签名，只把 URL、签名头与摘要交给子进程，不传长期 OSS 密钥。选定 namespace 配置版本目录和两款 SHA256，缺省不启用自动补装，保留原有缺包兼容。

默认 OSS 公网域名拒绝 APK 查询参数签名 URL 下载，故采用官方支持的 Authorization 请求头签名。签名由已有 OSS SDK 生成，限定 GET、Bucket 和对象路径；Date 限制请求时间偏差，下载器只接受必要签名头且不跟随重定向。参见[阿里云 APK 下载说明](https://help.aliyun.com/en/oss/what-to-do-with-apkdownloadforbidden-reporting-an-error)。

启动后读取当前实例包列表，仅下载缺失包；两款都缺时先抓号器、后上号器。缓存按 SHA256 命名，唯一临时文件、限时限量下载、完整摘要验证后原子替换。下载不持雷电 bindings.lock。安装前重新检查实例所有权、serial 和包是否仍缺失，使用无覆盖参数的 ADB install，完成后复查。

失败记录不含 URL 或凭据，回到原 QQ 分支；原截止时间到达或实例所有权失效不能继续操作。已有上号器可能接管 QQ 登录，因此回退只代表继续尝试原流程，不保证仍能获得旧二维码，也不自动卸载或禁用用户现有应用。无版本升级、无 APK 自动覆盖、无新增客户端或数据库接口。

发布采用已通过签名、包名和版本检查的 2026-10-24 QQ-Auto 两包。测试与正式 OSS 各保存独立私有对象；Cloudflare 各 namespace 只配置同环境版本目录与摘要。代码经 MR 进入 main，不重启运行中的正式任务。
